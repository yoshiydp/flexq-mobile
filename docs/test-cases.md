# FlexQ 動作確認テスト

テスター向けの全機能テストケース集です。画面ごと・機能ごとにケースを分けています。
上から順に実施すると、アカウント作成 → データ作成 → 各機能の確認、と自然な流れになるように並べています。

## はじめに

### 準備するもの

- **テスト端末**: iPhone(TestFlight)または Android(Google Play 内部テスト)。招待リンクからアプリをインストールしてください。同時再生(セクション 13)のテストは **iPhone は build 27 以上、Android はバージョンコード 13 以上**で行ってください(再生画面下部の開発用文字列に `engine=audio-api` と出ていれば対象のビルドです)
- **音源ファイル**: mp3 または wav を 2〜3 曲、端末の「ファイル」アプリ(iOS)/「ダウンロード」フォルダ(Android)に入れておいてください
- **イヤホン**: 有線または Bluetooth(録音・同時再生のテストで使います)
- **環境**: マイクで録音するため、声を出せる場所で実施してください

### 機内モードにするケースについて

PE-10 / AI-07 / SY-25 / CM-01 など「機内モードにする」ケースでは、機内モードを ON にしたあと **Wi-Fi のアイコンも OFF になっていることを確認**してから操作してください。一度でも機内モード中に Wi-Fi を ON にしたことがある端末では、以後は機内モードにしても Wi-Fi がつながったままになります(iPhone / Android 共通)。Wi-Fi がついたままだと通信エラーのケースは再現できず、成功してしまいます。

### 結果の報告方法

- 各ケースの「期待される結果」と違う動きをしたら **NG** です
- NG の場合は「**ケース番号**(例: PE-10)+ 実際に起きたこと + 可能ならスクリーンショット/画面録画」を送ってください
- アプリが落ちた・固まった場合は、直前に何をしていたかを添えてください
- 「期待どおりだけど使いにくい・分かりにくい」という感想も大歓迎です(番号+コメントで送ってください)

### 時間がないとき(最低限チェック)

次の 10 ケースだけでも主要機能を一巡できます:
RG-03(登録)→ NP-05(プロジェクト作成)→ PE-01(編集・保存)→ CU-01(CUE)→ PR-05(トラックを聴きながら録音)→ RP-02(録音の保存)→ AI-02(AI クリーンアップ)→ TL-02(トラック追加)→ QM-05(メモ)→ PF-03(ログアウト)

## 12. AI クリーンアップ(AI)

録音からトラックのかぶり音や周囲のノイズを取り除き、声だけを取り出す機能です。処理はサーバー(外部の AI)で行われ、完了まで数十秒〜1 分ほどかかります。
録音したときのイヤホンの有無で処理の種類が自動で選ばれます(イヤホンなし → トラックのかぶり音を分離 / イヤホンあり → ノイズ除去)。
処理はサーバー側で進むため、「処理中…」の間に画面を閉じたりアプリを終了したりしても処理は続きます。

| No | 確認すること | 手順 | 期待される結果 |
|----|----|----|----|
| AI-01 | 保存前は実行不可 | 録音直後(未保存)の画面で AI クリーンアップボタンを見る | ボタンがグレーで押せず、「保存すると実行できます」と表示されている |
| AI-02 | 手動実行 | 保存済みのプロジェクト録音を開いて AI クリーンアップをタップ | ボタンがくるくる付きの「処理中…」に変わる。完了すると「処理中…」が消え、タイトルの下に「元の録音 / 声のみ」の切り替えが表示される(AI クリーンアップボタンは表示されなくなる)。処理中も再生・シーク・音量などの操作はそのまま使える |
| AI-03 | 声のみ再生(イヤホンなし録音) | イヤホンなしでトラックを聴きながら録音したデータで「声のみ」を選び、再生する | 初回は数秒のローディング(ダウンロード)が出た後、声だけが再生される。トラックのかぶり音が消えている。冒頭が途切れ途切れ(カクつき)にならず、再生ボタンを押してすぐ(1 秒以内)に鳴り始める。「音源のダウンロードに失敗したため…」のアラートが出た場合は AI-16 を確認する |
| AI-04 | 元の録音に戻す | 「声のみ」を再生中に「元の録音」をタップ → 再生ボタン | タップした時点で再生が止まり、位置が先頭に戻る。再生ボタンで元の録音(かぶり音入り)がそのまま再生される |
| AI-05 | 録音前の自動実行設定 | QUICK RECORD 画面(または録音開始位置の選択画面)で「AI クリーンアップ」を ON にして録音 → 保存 | 保存後に自動で処理が始まる(一覧からその録音を開き直すと「処理中…」または「元の録音 / 声のみ」の切り替えになっている)。ON/OFF はアプリを再起動しても記憶されている。設定は QUICK RECORD と録音開始位置の選択画面で共通(一方で ON にするともう一方も ON) |

## 13. トラック同時再生(SY)

プロジェクトの録音を、トラック(伴奏)と重ねて再生する機能です。録音の再生画面に「トラック同時再生」スイッチが表示されます(クイック録音には表示されません)。
同時再生に使う音源(録音・声のみ・トラック)は、初回にダウンロードしてから再生します。そのため初めて同時再生を ON にしたときや、初めて「声のみ」を選んだときにローディングが出ます(2 回目以降は出ません)。
声とトラックは 1 つの時計に合わせて同時に鳴らす仕組み(TASK-121)のため、iPhone / Android のどちらでも、再生・シーク・リピートのたびにタイミングを合わせ直す待ち時間はありません。**再生ボタンを押した直後から声とトラックが同時に鳴り始めます**(以前の Android にあった「最初の 1 秒ほど無音」はなくなっています)。

> **古い Android の録音について:** バージョンコード 13 より前の Android で録音したテイクは、録音の開始位置が 0.1 秒ほどずれて保存されており、同時再生でトラックが少し遅れて聞こえます(iPhone で再生しても同じ)。これは直せないため、同時再生のテストには **バージョンコード 13 以上の Android、または iPhone で録音し直したテイク**を使ってください。

> **ズレを報告するとき:** テスト用のビルドでは再生画面の下部に `source=… sync=… offset=… start=… track=… engine=audio-api` という開発用の文字列が表示されます。タイミングのズレを感じたら、そのときの `offset` の値(例: `offset=+120ms`)と `track=` の値(`local` / `remote`)、録音した端末(iPhone / Android)を添えて報告してください。`offset` はプラスで「声が遅れて聞こえる」、マイナスで「声が先行して聞こえる」を表します。新しい仕組みでは `offset` は常に ±10ms 以内になるはずなので、それより大きい値が出ていたら値だけでも報告してください(ズレを感じなくても NG です)。

**音声入力はプラットフォームで仕様が異なります。** アプリ内のマイクボタン(QM-03 / QM-03-2〜QM-03-5)は **Android のみ**の機能です。iOS は認識結果が本文に入るまでの待ち時間が長く、端末標準の音声入力の方が速度・精度とも優れていたため、アプリのマイクボタンは廃止し **OS 標準のキーボード音声入力(ディクテーション)に一本化**しました(QM-03-1)。iOS でツールバーにマイクボタンが出ていたら NG です。

音声入力のケースはいずれも E2E 自動テスト(Maestro)の対象外です。実際の発話が必要なうえ、iOS シミュレーター・Android エミュレーターでは音声認識サービスが使えるかどうかが環境に依存し、マイク・音声認識の許可状態も Maestro の clearState / clearKeychain では初期化できないため、マイクボタンの点灯や案内表示の結果が安定しません。実機での手動確認で実施してください。
