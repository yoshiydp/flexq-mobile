## 2. 背景

### 2-1. SES の「サンドボックス」状態

FlexQ は新規登録やパスワード再設定の際にユーザーへメールを送信しており、この送信に AWS の SES（Simple Email Service）を使用しています。
SES は契約直後は「サンドボックス（お試しモード）」の状態で、**事前に登録した特定のメールアドレス（現在は開発者のアドレス 1 件のみ）にしかメールを送信できません**。
一般ユーザーにメールを届けるには、AWS に「本番アクセス」を申請して承認を受ける必要があります。

### 2-2. リリース前に修正が必須の脆弱性

現在のアプリには、リリース前に必ず修正すべき問題が 2 つあります。

| 問題 | 内容 |
|------|------|
| パスワード再設定に本人確認がない | 「パスワードを忘れた場合」の画面で、メールアドレスを入力するだけで誰でもそのアカウントのパスワードを書き換えられる。他人のメールアドレスを知っていればアカウントを乗っ取れる |
| 新規登録にメール確認がない | 実在しないメールアドレスや他人のメールアドレスで登録できてしまう |

対策として、**メールで届く 6 桁の認証コードによる 2 段階の本人確認**を導入します（銀行や SNS のログイン時に届く認証コードと同じ仕組み）。

- 新規登録: メールに届いた 6 桁コードを入力した人だけが登録できる
- パスワード再設定: メールに届いた 6 桁コードを入力した本人だけがパスワードを変更できる

この仕組みは「すべてのユーザーにメールが届くこと」が前提です。SES がサンドボックスのままだと認証コードが届かず、**新規登録とパスワード再設定が全ユーザーで不能になります**。そのため SES の本番アクセス承認がリリースの必須条件になっています。
また、ストア審査でも審査担当者が「パスワードを忘れた場合」を操作して審査用アカウントのパスワードが書き換わるリスクがあり、この修正は App Store / Google Play の審査通過にも直接関わります。

### 2-3. 運営者アカウントでの手動申請が必要な理由

- SES は運営者名義の AWS アカウント（本番環境）で稼働している
- 2026 年 8 月に開発者がプログラム経由で申請したが**却下**された（Case ID: 178610197900611。申請時の Web サイト URL が公開前の TestFlight 招待リンクだったことが原因と推定）
- 一度却下されるとプログラム経由での再申請はできず、AWS 管理画面（コンソール）からの手動申請のみが可能
- 今回は公式サイト（https://flexqstudio.com）を案内し、認証コード導入を申請文に含めているため承認の見込みは高い

## 4. 操作手順

### ステップ 1: AWS 管理画面にログインする

1. ブラウザで https://console.aws.amazon.com/ を開く
2. 「ルートユーザー」を選択し、AWS アカウント作成時のメールアドレスとパスワードでログインする
   - 2 段階認証（MFA）を設定している場合は、認証アプリの 6 桁コードを入力する
3. ログイン後、画面右上のリージョン表示が **「東京」** になっていることを確認する
   - 「バージニア北部」など別リージョンの場合はクリックし、**「アジアパシフィック（東京）ap-northeast-1」** を選択する
   - FlexQ のメール送信は東京リージョンに設定されているため、ここが異なると申請先がずれる

### ステップ 2: SES の画面を開く

1. 画面上部の検索窓に `SES` と入力する
2. 候補の **「Amazon Simple Email Service」** をクリックする
3. 左メニューの **「アカウントダッシュボード」** をクリックする
4. 画面上部に「アカウントはサンドボックス状態です」という趣旨の案内と **「本番アクセスをリクエスト」**（Request production access）ボタンが表示される

### ステップ 3-A: 「本番アクセスをリクエスト」ボタンが押せる場合

1. **「本番アクセスをリクエスト」** をクリックする
2. フォームを以下のとおり入力する

| 項目 | 入力内容 |
|------|---------|
| メールタイプ | **トランザクション**（Transactional） |
| ウェブサイト URL | `https://flexqstudio.com` |
| ユースケースの説明 | 「5. 申請文」を全文コピーして貼り付け |
| 追加の連絡先（任意） | `yoshihisa.watanabe.info@gmail.com`（開発者にも AWS からの連絡が届くようにする） |
| 優先する連絡先言語 | **日本語** |
| 同意のチェックボックス | 内容を確認してチェック |

3. **「リクエストを送信」** をクリックする
4. 「リクエストを受け付けました」という趣旨の画面が表示されたら完了。**画面のスクリーンショットを開発者へ送る**

### ステップ 3-B: ボタンが無い、または押せない場合

前回の却下の影響でボタンが使えない場合は、サポートセンターから申請する。

1. 画面右上の **「？」アイコン** をクリックし **「サポートセンター」** を選択する
2. **「ケースを作成」**（Create case）をクリックする
3. **「サービス制限の緩和」**（Looking for service limit increases?）を選択する
4. フォームを以下のとおり入力する

| 項目 | 入力内容 |
|------|---------|
| 制限タイプ / サービス | **SES 送信制限**（SES Sending Limits）または **Amazon SES** |
| メールタイプ | **トランザクション** |
| ウェブサイト URL | `https://flexqstudio.com` |
| ユースケースの説明 | 「5. 申請文」を全文コピーして貼り付け |
| リクエスト 1 → リージョン | **アジアパシフィック（東京）** |
| リクエスト 1 → 制限 | **Desired Daily Sending Quota**（1 日の送信上限） |
| リクエスト 1 → 新しい制限値 | `1000` |
| 連絡方法 | **Web** |
| 言語 | **日本語** |

5. **「送信」** をクリックする
6. ケース ID（数字の列）が表示された画面の**スクリーンショットを開発者へ送る**

> 補足: サポートセンターのケース一覧に前回のケース **ID: 178610197900611** が残っている場合は、そのケースを開いて「返信」から申請文を貼り付け、再審査を依頼する方法でもよい。どちらか一方で足りる。

### ステップ 4: 申請後の対応

| 状況 | 対応 |
|------|------|
| 通常 1〜2 営業日で AWS から結果のメールが届く | AWS アカウントの登録メールアドレス宛に届く |
| 「追加の情報をください」という返信が来た | メールをそのまま開発者へ転送する（回答文は開発者が用意する） |
| 「本番アクセスが承認されました」というメールが届いた | 開発者へ連絡する。開発者が設定の反映を確認し、認証コードメールの送信テストを行う |

【送信するメールの種類（すべて利用者本人の操作を起点とする 1 通ずつのトランザクションメール）】
1. 新規登録時の 6 桁認証コード（ダブルオプトイン）: 利用者がアプリで自分のメールアドレスを入力すると認証コードを送信し、コードが正しく入力された場合のみアカウントを作成します。入力されたアドレスが本人のものであることを確認してから初めて登録が成立するため、実在しない・他人のアドレスへの継続送信は発生しません。
2. パスワードリセット時の 6 桁認証コード: 利用者がアプリの「パスワードを忘れた場合」を操作したときに、登録済みアドレスにのみ送信します。
3. 登録完了・パスワード変更完了の通知メール（上記 1・2 の直後に 1 通）。

マーケティングメール・ニュースレター・一斉配信は一切行いません。送信内容はすべてアプリ内のセキュリティ操作に対する応答で、利用者が期待している通知のみです。

【受信者リストの取得方法】
受信者はアプリで自らメールアドレスを登録した利用者本人のみです。購入リスト・第三者から提供されたリスト・スクレイピング等による宛先は一切使用しません。また、認証コードを使ったダブルオプトインにより、所有確認が取れていないアドレスへは認証コード以外を送信しません。認証コードの送信には 60 秒間隔の再送制限と有効期限（10 分）・試行回数上限を設けており、同一アドレスへの連続送信を防いでいます。

【想定送信量】
当面は 1 日あたり数通〜数十通程度、公開後の増加を見込んでも 1 日 200 通以内、最大でも 1,000 通/日程度を想定しています。送信レートは 1 通/秒以内です。

【バウンス・苦情の管理】
・SES アカウントレベルのサプレッションリスト（バウンス・苦情の両方）を有効化しており、バウンス・苦情が発生した宛先には自動的に再送しません。
・送信元 ID（yoshihisa.watanabe.info@gmail.com）へのフィードバック転送を有効化しており、バウンス・苦情通知を受信して即時に確認します。
・バウンス率・苦情率は SES コンソールのレピュテーションメトリクスと CloudWatch で監視し、閾値を超えた場合は送信を停止して原因を調査します。
・ダブルオプトインにより登録時点で存在しないアドレスを排除するため、ハードバウンスの発生は構造的に最小化されます。

【送信元】
送信元アドレスは検証済みの yoshihisa.watanabe.info@gmail.com（開発者）です。リージョンは ap-northeast-1（東京）、送信は AWS Lambda（Node.js SDK v3）から SendEmail API で行います。

前回の申請（Case ID 178610197900611）では Web サイト URL が TestFlight の招待リンクになっていましたが、本申請では公式サイトに差し替え、認証コードによるダブルオプトインの導入を含めて用途を具体化しています。ご不明点があれば追加情報を提出しますので、ご連絡ください。
